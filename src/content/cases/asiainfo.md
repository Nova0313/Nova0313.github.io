## 问题

办公提效 Agent 在本地小模型环境下，需要兼顾运行稳定性、输出可控性与可衡量的使用效果。只有功能运行起来，还不足以指导下一轮产品迭代。

## 我的角色与判断

我参与 HelmClaw 从架构方向、Skill 管理体验到评测体系的产品工作，将调研结论转化为 MVP 范围、功能需求和可复用的评测方法。

## 做法

### Agent 架构调研与选型

研究 Agent 记忆、Agent / Skill 检索与路由、自进化等方向，参考 MemPalace、OpenClaw、Hermes 等开源框架及相关论文，形成架构选型和产品方向建议，支持 MVP 范围界定。

### Skill 功能设计

对标 SkillHub、DarwinSkill 等产品与开源生态，梳理 Skill 创建、分类标签、安全与质量检查、版本发布等 5 项功能的需求与 PRD。使用 Codex、Trae 构建覆盖管理侧与用户侧、3 个核心场景的交互原型，并与研发及前端协作推进落地。

### HybridJudge 评测体系

人工标注 200 条多轮会话作为评测集，对比 6 个国内主流模型。设计“LLM 语义理解 + 规则校验”的混合流水线，再用分析脚本定位任务理解和工具调用问题，反馈给研发团队。

## 结果

评估结果与人工标注的对齐度由 72% 提升至 93%。评测方法让问题定位和方案迭代有了共同依据。
